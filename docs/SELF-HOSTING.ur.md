# فاروق بز مینیجر اپنے سرور پر

یہ رہنمائی آئی ٹی والوں کے لیے ہے جو ڈیٹا اپنی مشین پر رکھنا چاہتے ہیں — دفتر کا سرور، گھر کا سرور، یا کرائے کا ورچوئل سرور۔
اگر صرف چلانا مقصود ہے تو [مفت کلاؤڈ والا طریقہ](INSTALL.ur.md) کہیں آسان ہے۔

> **پہلے خود سے ایمان داری:** اپنے سرور پر چلانے والے *آپ* ہیں۔
> حفاظتی اپڈیٹ، بیک اپ، ڈسک کی جگہ اور سرور کا چلتے رہنا — سب آپ کی ذمہ داری ہے۔
> حساب کتاب کا ڈیٹا قیمتی ہے: سرور خراب ہو اور بیک اپ نہ ہو، تو کھاتے ختم۔

---

## 1. کیا کہاں چلتا ہے

```
 Browser (staff, phone, PC)
        │  https://app.example.com         ← the website (static files)
        │  https://api.example.com         ← Convex backend, port 3210
        │  https://site.example.com        ← Convex HTTP actions, port 3211
        ▼
 ┌──────────────────────── your server ────────────────────────┐
 │  Caddy (HTTPS + serves the website files)                    │
 │  Convex backend  (Docker)  ── database (SQLite or Postgres)  │
 │  Convex dashboard (Docker, private — never on the internet)  │
 └──────────────────────────────────────────────────────────────┘
```

- **ویب سائٹ:** بنانے کے بعد سادہ فائلیں (`dist/`)۔ کوئی بھی ویب سرور انہیں دکھا سکتا ہے۔
- **Convex سرور:** اوپن سورس سرور جو ڈیٹا رکھتا ہے اور حساب کتاب کا ہر اصول چلاتا ہے۔ اس کی سرکاری Docker تصاویر موجود ہیں۔
- **سائن اِن:** ایپ کے اندر بنا ہوا ہے۔ اس کے لیے سرور کو اپنے `site` والے پتے تک خود پہنچنا ہوتا ہے (`/.well-known/jwks.json` پڑھنے کے لیے)، اس لیے وہ پتہ *سرور کے اندر سے* بھی کھلنا چاہیے۔

## 2. کیا چاہیے

| چیز | کم از کم | آرام دہ |
|---|---|---|
| سرور | لینکس (Ubuntu 22.04/24.04)، 2 پروسیسر، 4 GB میموری | 4 پروسیسر، 8 GB میموری |
| ڈسک | 40 GB SSD | 100 GB SSD + بیک اپ کے لیے الگ ڈسک |
| سافٹ ویئر | Docker اور Docker Compose | + Caddy بطور ریورس پراکسی |
| بنانے کی مشین | Node.js 20 یا نیا، اور pnpm (سرور خود بھی ہو سکتا ہے) | |
| ڈومین | ایک ڈومین، تین ذیلی نام (app، api، site) | |
| بیک اپ کی جگہ | دوسری جگہ: الگ ڈسک، NAS، یا کلاؤڈ اسٹوریج | دو جگہیں، ایک عمارت سے باہر |

اندازاً خرچ: چھوٹا کرائے کا سرور عموماً چند ڈالر سے تقریباً 20 امریکی ڈالر ماہانہ، ڈومین تقریباً 10 سے 15 ڈالر سالانہ (قیمتیں کمپنی اور ملک کے حساب سے بدلتی ہیں)۔
دفتر یا گھر کا سرور صرف بجلی کا خرچ لیتا ہے، مگر بجلی جانا، انٹرنیٹ بند ہونا اور ہارڈویئر خراب ہونا پھر آپ کی ذمہ داری ہے۔

## 3. تنصیب، قدم بہ قدم

### 3.1 سرور کی تیاری
1. Ubuntu لگائیں، `sudo` والا عام صارف بنائیں، خودکار حفاظتی اپڈیٹ چالو کریں۔
2. فائر وال: باہر سے صرف **22** (SSH)، **80** اور **443** کھلے رہیں۔ اور کچھ نہیں۔
3. Docker اور Docker Compose لگائیں۔

### 3.2 Convex سرور چلائیں
سرکاری رہنمائی کے مطابق چلائیں — اس میں تازہ ترین `docker-compose.yml` ہے:
**https://github.com/get-convex/convex-backend/tree/main/self-hosted**

اس فائل کی اہم ترتیبات:
- `CONVEX_CLOUD_ORIGIN` = `https://api.example.com` (پورٹ 3210 کا عوامی پتہ)
- `CONVEX_SITE_ORIGIN` = `https://site.example.com` (پورٹ 3211 کا عوامی پتہ)
- ڈیٹا والا حصہ ایسی ڈسک پر رکھیں جس کا بیک اپ ہوتا ہو

چلانے کے بعد رہنمائی کے مطابق **منتظم کی چابی** بنائیں۔ یہ آپ کے ڈیٹا کی سب سے بڑی چابی ہے — اسے پاس ورڈ رکھنے والی ایپ میں رکھیں، ریپو کی کسی فائل میں کبھی نہیں۔

**ڈیش بورڈ** کو نجی رکھیں: صرف `localhost` پر، اور SSH سرنگ یا VPN (مثلاً Tailscale) سے کھولیں۔ انٹرنیٹ پر کبھی نہیں۔

### 3.3 ڈومین اور محفوظ کنکشن
`app`، `api` اور `site` کو اپنے سرور کے IP پر لگائیں۔ Caddy کے ساتھ محفوظ کنکشن کے سرٹیفکیٹ خود بن جاتے ہیں۔ مثال `Caddyfile`:

```
app.example.com {
    root * /srv/bizmanager/dist
    try_files {path} /index.html
    file_server
}
api.example.com {
    reverse_proxy localhost:3210
}
site.example.com {
    reverse_proxy localhost:3211
}
```

`try_files … /index.html` ضروری ہے: ایپ کے صفحات براؤزر کے راستے ہیں، اور سب کو `index.html` پر واپس آنا چاہیے۔

### 3.4 ایپ کو سرور پر چڑھائیں اور ویب سائٹ بنائیں
بنانے والی مشین پر:

```bash
git clone https://github.com/FarooqStars/farooq-bizmanager.git
cd farooq-bizmanager
pnpm install
```

فائل `.env.local` بنائیں (گٹ اسے نظرانداز کرتا ہے — یہ کبھی گٹ ہب پر نہیں جاتی):

```
CONVEX_SELF_HOSTED_URL=https://api.example.com
CONVEX_SELF_HOSTED_ADMIN_KEY=<your admin key>
VITE_CONVEX_URL=https://api.example.com
```

پھر:

```bash
npx convex deploy     # sends the server code and database schema
pnpm build            # makes the website in dist/
```

`dist/` کو سرور پر یہاں رکھیں:
```
/srv/bizmanager/dist
```

### 3.5 پہلی بار کی ترتیب
`https://app.example.com` **فوراً** کھولیں اور مالک کا اکاؤنٹ بنائیں — نئی تنصیب پر جو پہلے کھولے، وہی مالک بنتا ہے۔

### 3.6 ای میل (اختیاری)
```bash
npx convex env set RESEND_API_KEY <your key>
```

## 4. بیک اپ — سب سے اہم حصہ

**3-2-1 کا اصول** اپنائیں: ڈیٹا کی **3** نقلیں، **2** مختلف قسم کی جگہوں پر، اور **1** نقل کسی دوسری عمارت میں۔

1. **روزانہ** سارے ڈیٹا کی زپ نکالیں (پروجیکٹ کے فولڈر سے، جہاں `.env.local` ہو):
   ```bash
   npx convex export --path /backups/bizmanager-$(date +%F).zip
   ```
   اسے cron سے خودکار کریں، مثلاً ہر رات 2 بجے:
   ```
   0 2 * * *  cd /srv/bizmanager-src && npx convex export --path /backups/bizmanager-$(date +\%F).zip
   ```
2. **رکھیں:** روزانہ والی 14 دن، ہفتہ وار 3 مہینے، ماہانہ ایک سال۔
3. **ہر رات باہر نقل:** دوسری عمارت، NAS، یا کلاؤڈ اسٹوریج (مثلاً `rclone` سے)۔
4. **باہر والی نقلیں خفیہ کریں** — ان میں گاہک، تنخواہیں اور بینک کی معلومات ہیں۔
5. **ہر مہینے واپسی آزمائیں**، کسی فالتو مشین یا آزمائشی سرور پر۔ جس بیک اپ کو کبھی واپس نہیں لایا گیا، وہ صرف ایک امید ہے:
   ```bash
   npx convex import --replace-all /backups/bizmanager-YYYY-MM-DD.zip   # ONLY on a test backend
   ```
6. ہر اپڈیٹ سے پہلے ایک اضافی زپ نکالیں۔

زپ نکالنے اور واپس لانے کے تازہ طریقے Convex کی سرکاری دستاویزات میں دیکھیں:
**https://docs.convex.dev**

## 5. اپڈیٹ

**ایپ کا نیا ورژن:**
```bash
npx convex export --path /backups/before-update-$(date +%F).zip
git pull
pnpm install
pnpm test            # all tests must pass
npx convex deploy
pnpm build           # then copy dist/ to the server again
```

**Convex سرور کا نیا ورژن:** پہلے زپ نکالیں، پھر سرکاری رہنمائی کے مطابق نئی تصاویر لے کر دوبارہ چلائیں۔ ان کی تبدیلیوں کی تفصیل ضرور پڑھیں۔

**سرور:** خودکار حفاظتی اپڈیٹ چالو رکھیں؛ بنیادی نظام بدلے تو خاموش وقت میں دوبارہ چلائیں۔

## 6. حفاظت کی فہرست

- [ ] صرف 80، 443 اور SSH کھلے؛ SSH چابی سے، پاس ورڈ سے داخلہ بند
- [ ] ڈیش بورڈ صرف SSH سرنگ یا VPN سے
- [ ] منتظم کی چابی پاس ورڈ ایپ میں، کسی مشترکہ فائل یا چیٹ میں نہیں
- [ ] `.env.local` کبھی جمع نہیں (یہ `.gitignore` میں ہے)
- [ ] تینوں پتوں پر محفوظ کنکشن
- [ ] تنصیب کے فوراً بعد مالک کا اکاؤنٹ
- [ ] ہر شخص اپنا اکاؤنٹ؛ جو چھوڑ جائے اسے فوراً بند کریں
- [ ] اصلی ڈیٹا والے سرور پر `DEMO_MODE` کبھی نہیں — اس کی رات کی صفائی سب کچھ مٹا دیتی ہے

## 7. نگرانی

- `https://app.example.com` پر چلتے رہنے کی جانچ (کئی مفت سروسیں ہیں) جو بند ہونے پر آپ کو ای میل کرے۔
- ہفتے میں ایک بار ڈسک کی خالی جگہ (`df -h`) — ڈسک بھر جائے تو ڈیٹا بیس رک جاتا ہے۔
- ایپ کے اندر: **رپورٹیں ← ملان کا پینل** — کوئی جانچ سرخ ہو تو مہینہ بند کرنے سے پہلے وجہ دیکھیں۔

## 8. کیا جانچا گیا

ایپ کو لینکس پر اپنے Convex سرور کے ساتھ جانچا گیا: کوڈ چڑھانا، سائن اِن (بشمول `.well-known/jwks.json` کی جانچ)، اور پوری فرضی کمپنی بنانا۔ 131 خودکار ٹیسٹ بھی کامیاب ہیں۔
اوپر والی Docker Compose اور Caddy کی ترتیبات سرکاری دستاویزات کے مطابق ہیں، مگر آپ کے سرور پر منحصر ہیں — پہلے کسی فالتو مشین پر آزمائیں۔
