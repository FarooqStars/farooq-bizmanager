# تشغيل فاروق بيز مانجر على خادمك الخاص

هذا الدليل لفنيي تقنية المعلومات الذين يريدون البيانات على جهاز يتحكمون فيه — خادم المكتب، أو خادم منزلي، أو خادم افتراضي مستأجر.
إن كنت تريد تشغيله فقط، فإن [طريقة السحابة المجانية](INSTALL.ar.md) أسهل بكثير.

> **كن صريحاً مع نفسك أولاً:** على خادمك الخاص *أنت* المشغّل.
> التحديثات الأمنية والنسخ الاحتياطي ومساحة القرص واستمرار التشغيل كلها مسؤوليتك.
> بيانات المحاسبة ثمينة: إذا تعطل الخادم ولم توجد نسخة احتياطية، ضاعت الدفاتر.

---

## 1. ما الذي يعمل وأين

```
 Browser (staff, phone, PC)
        │  https://app.example.com         ← the website (static files)
        │  https://api.example.com         ← Convex backend, port 3210
        │  https://site.example.com        ← Convex HTTP actions, port 3211
        ▼
 ┌──────────────────────── your server ────────────────────────┐
 │  Caddy (HTTPS + serves the website files)                    │
 │  Convex backend  (Docker)  ── database (SQLite or Postgres)  │
 │  Convex dashboard (Docker, private — never on the internet)  │
 └──────────────────────────────────────────────────────────────┘
```

- **الموقع:** ملفات عادية (`dist/`) بعد البناء. أي خادم ويب يستطيع عرضها.
- **خادم Convex:** خادم مفتوح المصدر يحفظ البيانات وينفّذ كل قاعدة محاسبية. له صور Docker رسمية.
- **تسجيل الدخول:** مدمج في البرنامج. يحتاج الخادم إلى الوصول إلى عنوان `site` الخاص به (لقراءة `/.well-known/jwks.json`)، لذا يجب أن يعمل هذا العنوان *من داخل الخادم نفسه* أيضاً.

## 2. ما تحتاج إليه

| العنصر | الحد الأدنى | المريح |
|---|---|---|
| الخادم | لينكس (Ubuntu 22.04/24.04)، معالجان، ذاكرة 4 GB | 4 معالجات، ذاكرة 8 GB |
| القرص | SSD بسعة 40 GB | SSD بسعة 100 GB + قرص منفصل للنسخ الاحتياطي |
| البرمجيات | Docker و Docker Compose | + Caddy كوكيل عكسي |
| جهاز البناء | Node.js 20 أو أحدث و pnpm (يمكن أن يكون الخادم نفسه) | |
| النطاق | نطاق واحد بثلاثة نطاقات فرعية (app و api و site) | |
| مكان النسخ الاحتياطي | مكان ثانٍ: قرص آخر أو NAS أو تخزين سحابي | مكانان، أحدهما خارج المبنى |

التكلفة التقريبية: الخادم الافتراضي الصغير عادةً من بضعة دولارات إلى نحو 20 دولاراً أمريكياً شهرياً، والنطاق نحو 10 إلى 15 دولاراً سنوياً (تختلف الأسعار حسب الشركة والدولة).
خادم المكتب أو المنزل لا يكلّف إلا الكهرباء، لكن انقطاع الكهرباء والإنترنت وأعطال الأجهزة تصبح مسؤوليتك.

## 3. التثبيت خطوة بخطوة

### 3.1 تجهيز الخادم
1. ثبّت Ubuntu، وأنشئ مستخدماً عادياً بصلاحية `sudo`، وفعّل التحديثات الأمنية التلقائية.
2. الجدار الناري: اسمح فقط بالمنافذ **22** (SSH) و **80** و **443** من الخارج. لا شيء غيرها.
3. ثبّت Docker و Docker Compose.

### 3.2 شغّل خادم Convex
اتبع الدليل الرسمي — ففيه أحدث ملف `docker-compose.yml`:
**https://github.com/get-convex/convex-backend/tree/main/self-hosted**

الإعدادات المهمة في ذلك الملف:
- `CONVEX_CLOUD_ORIGIN` = `https://api.example.com` (العنوان العام للمنفذ 3210)
- `CONVEX_SITE_ORIGIN` = `https://site.example.com` (العنوان العام للمنفذ 3211)
- ضع مجلد البيانات على قرص يُنسخ احتياطياً

بعد التشغيل أنشئ **مفتاح المدير** كما يشرح الدليل. إنه المفتاح الرئيسي لبياناتك — احفظه في تطبيق لإدارة كلمات المرور، ولا تضعه أبداً في أي ملف داخل المستودع.

أبقِ **لوحة التحكم** خاصة: اربطها بـ `localhost` وافتحها عبر نفق SSH أو شبكة VPN (مثل Tailscale)، ولا تفتحها على الإنترنت أبداً.

### 3.3 النطاق والاتصال الآمن
وجّه `app` و `api` و `site` إلى عنوان IP الخاص بخادمك. مع Caddy تُنشأ شهادات الاتصال الآمن تلقائياً. مثال `Caddyfile`:

```
app.example.com {
    root * /srv/bizmanager/dist
    try_files {path} /index.html
    file_server
}
api.example.com {
    reverse_proxy localhost:3210
}
site.example.com {
    reverse_proxy localhost:3211
}
```

السطر `try_files … /index.html` ضروري: صفحات البرنامج مسارات داخل المتصفح، ويجب أن تعود كلها إلى `index.html`.

### 3.4 ارفع البرنامج إلى الخادم وابنِ الموقع
على جهاز البناء:

```bash
git clone https://github.com/FarooqStars/farooq-bizmanager.git
cd farooq-bizmanager
pnpm install
```

أنشئ الملف `.env.local` (يتجاهله git — لا يذهب إلى GitHub أبداً):

```
CONVEX_SELF_HOSTED_URL=https://api.example.com
CONVEX_SELF_HOSTED_ADMIN_KEY=<your admin key>
VITE_CONVEX_URL=https://api.example.com
```

ثم:

```bash
npx convex deploy     # sends the server code and database schema
pnpm build            # makes the website in dist/
```

انسخ `dist/` إلى هذا المكان على الخادم:
```
/srv/bizmanager/dist
```

### 3.5 الإعداد لأول مرة
افتح `https://app.example.com` **فوراً** وأنشئ حساب المالك — في التثبيت الجديد، أول من يفتح الموقع يصبح المالك.

### 3.6 البريد الإلكتروني (اختياري)
```bash
npx convex env set RESEND_API_KEY <your key>
```

## 4. النسخ الاحتياطي — أهم جزء

اتبع **قاعدة 3-2-1**: **3** نسخ من البيانات، على **2** نوعين مختلفين من التخزين، ونسخة **1** في مكان آخر خارج المبنى.

1. **يومياً** صدّر كل البيانات إلى ملف zip (من مجلد المشروع الذي فيه `.env.local`):
   ```bash
   npx convex export --path /backups/bizmanager-$(date +%F).zip
   ```
   جدوِله عبر cron، مثلاً كل ليلة الساعة 2:
   ```
   0 2 * * *  cd /srv/bizmanager-src && npx convex export --path /backups/bizmanager-$(date +\%F).zip
   ```
2. **احتفظ** بالنسخ اليومية 14 يوماً، والأسبوعية 3 أشهر، والشهرية سنة.
3. **انسخ خارج المبنى** كل ليلة: مبنى آخر أو NAS أو تخزين سحابي (مثلاً عبر `rclone`).
4. **شفّر** النسخ الخارجية — ففيها العملاء والرواتب والبيانات البنكية.
5. **جرّب الاستعادة** كل شهر على جهاز احتياطي أو خادم تجريبي. النسخة التي لم تُستعد قط مجرد أمل:
   ```bash
   npx convex import --replace-all /backups/bizmanager-YYYY-MM-DD.zip   # ONLY on a test backend
   ```
6. قبل كل تحديث: صدّر نسخة إضافية.

راجع التوثيق الرسمي لـ Convex لأحدث خيارات التصدير والاستيراد:
**https://docs.convex.dev**

## 5. التحديثات

**إصدار جديد من البرنامج:**
```bash
npx convex export --path /backups/before-update-$(date +%F).zip
git pull
pnpm install
pnpm test            # all tests must pass
npx convex deploy
pnpm build           # then copy dist/ to the server again
```

**إصدار جديد من خادم Convex:** صدّر نسخة أولاً، ثم اتبع الدليل الرسمي لسحب الصور الجديدة وإعادة التشغيل. اقرأ ملاحظات الإصدار.

**الخادم:** أبقِ التحديثات الأمنية التلقائية مفعّلة؛ وأعد التشغيل في وقت هادئ عند تحديث النواة.

## 6. قائمة الأمان

- [ ] المنافذ المفتوحة فقط 80 و 443 و SSH؛ الدخول إلى SSH بالمفاتيح وإيقاف الدخول بكلمة المرور
- [ ] لوحة التحكم عبر نفق SSH أو VPN فقط
- [ ] مفتاح المدير في تطبيق كلمات المرور، لا في ملف مشترك أو محادثة
- [ ] الملف `.env.local` لا يُرفع أبداً (موجود في `.gitignore`)
- [ ] اتصال آمن على العناوين الثلاثة
- [ ] إنشاء حساب المالك فور التثبيت
- [ ] لكل شخص حسابه؛ ومن يغادر يُوقف حسابه فوراً
- [ ] لا تضع `DEMO_MODE` أبداً على خادم فيه بيانات حقيقية — المسح الليلي يحذف كل شيء

## 7. المراقبة

- فحص استمرار التشغيل على `https://app.example.com` (توجد خدمات مجانية كثيرة) يرسل لك بريداً عند التوقف.
- نظرة أسبوعية على المساحة الفارغة (`df -h`) — امتلاء القرص يوقف قاعدة البيانات.
- داخل البرنامج: **التقارير ← لوحة المطابقة** — إذا احمرّ أي فحص، ابحث عن السبب قبل إقفال الشهر.

## 8. ما الذي تم اختباره

اختُبر البرنامج مع خادم Convex خاص على لينكس: رفع الكود، وتسجيل الدخول (بما فيه فحص `.well-known/jwks.json`)، وبناء الشركة التجريبية كاملة. كما تنجح الاختبارات الآلية الـ 131.
ملفات Docker Compose و Caddy أعلاه تتبع التوثيق الرسمي لكنها تعتمد على خادمك — جرّبها أولاً على جهاز احتياطي.
